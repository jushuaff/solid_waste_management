## Role and permission audit — 2026-11-25

**Source-level review only:** The six roles exist, but passing role-by-role integration tests has not been established. These open items must be resolved before any production or participant-data use.

### Verified role entry points (not full acceptance)
- [x] **Resident:** register, login, own missed-pickup and dumping reports (with photo/coordinate inputs), own status/history, rules, collection schedules and notifications.
- [x] **Crew:** access assigned complaint workflow (start, resolve, exception), record zone-scoped pickup inspections and read zone-scoped household references.
- [x] **Eco-aide:** zone-scoped inspection and MRF forms, read household registry and zone metrics.
- [x] **Coordinator:** configuration, incident assignment and closing, LINIS monitoring, monthly printable monitoring summary.
- [x] **Barangay administrator:** users, zones/categories, schedule/rule setup, complaints and LINIS records.
- [x] **Superadministrator:** same overall privileges plus ability to assign the superadmin role to accounts. Privilege boundaries need tightening.

### Security and business-logic gaps (all open)
- [ ] **RBAC-01 — Critical:** prevent ordinary admins from editing, changing the password of, demoting, disabling or deleting a *superadministrator* account. `ManagementController` currently checks the *new* role but not the target account's existing role.
- [ ] **RBAC-02 — Critical:** restrict incident listing, detail pages, printouts and private photo evidence to the resident owner, specifically assigned crew, designated coordinator, or permitted administrator. `ReportController` currently leaves the `eco_aide` role unscoped.
- [ ] **RBAC-03 — High:** enforce coordinator's zone restrictions on incident queries, incident actions and all management CRUD requests, not only LINIS operational CRUD.
- [ ] **RBAC-04 — High:** decide whether eco-aides/crew may edit each other's inspections and whether all eco-aides may edit MRF entries. Enforce owner/supervisor permissions at the controller layer; current `LinisController` allows role-level updates within an assigned zone.
- [ ] **RBAC-05 — High:** protect zone, category and user records referenced by the new household, inspection and MRF collections from destructive deletion; current old-resource deletion checks omit those new references.
- [ ] **RBAC-06 — High:** create automated authorization and negative-access tests for all six roles, including inactive users, cross-zone access, cross-resident access, photo download, and restricted settings.
- [ ] **RBAC-07 — Medium:** avoid a default resident role for users with missing/inconsistent role relationships; require valid roles when authenticating/authorizing old records.
- [ ] **RBAC-08 — Medium:** require zone-assigned collection crews where appropriate rather than allowing null-zone crew assignments across zones.
- [ ] **UX-01:** use neutral "Report an incident" wording throughout missed-pickup and illegal-dumping flows. Confirm usable mobile map controls and correction flow.
- [ ] **DATA-01:** test MRF calculations against manually verified sample weights, correction history, and six-month data. Validate the statutory denominator/report format with an actual LGU before regulatory claims.
- [ ] **OPS-01:** confirm Laravel scheduler is installed/running and hourly overdue/two-week alerts reach intended coordinator/admin only once.
- [ ] **TEST-01:** add real end-to-end MongoDB feature tests for every online CRUD, file evidence, role matrix, reset email and printable output.

## Shared data / workflow rules
- Inspections represent **observed pickups**; missed-pickup case reports are a separate dataset.
- Household data is minimal and linked to a zone. No real citizen data should be seeded for demonstrations.
- Compliance rate = compliant inspections / all inspections × 100 (avoid divide-by-zero; explain sample size).
- Diversion rate = diverted MRF weight / total recorded MRF weight × 100. Use only comparable logged weight categories and label this as a **record-based illustrative metric**; reconcile with the adopting LGU's officially required denominator before regulatory use.
- Dashboard thresholds for the academic prototype: green >=80%, yellow 60–79.99%, red <60%.
- Alerts need an automated cron/scheduler; an implemented command alone does not mean background scheduling is running.
- Report urgency threshold: over 48 h unresolved; escalation recipient is the designated active barangay admin/coordinator.
- Sample records and example collection arrangements do **not** establish an official barangay schedule or compliance claim.
- These data are isolated per barangay installation; shared multi-barangay hosting is out of scope.

## PHP 8.4 on Windows

Before installing, verify a PHP 8.4-compatible php.ini, OpenSSL, mbstring and the PHP MongoDB extension. See [PHP 8.4 Windows Setup](docs/PHP84_WINDOWS_SETUP.md). Do not disable Composer TLS.

## Local setup and acceptance commands
```powershell
php -v
where.exe php
php --ini
php -m | findstr /I "mongodb openssl mbstring fileinfo"
composer install
Copy-Item .env.example .env  # only if .env does not exist
php artisan key:generate
php artisan migrate
php artisan db:seed
php artisan route:list
php artisan test
php artisan serve
```

For periodic online alerts configure Laravel's scheduler (Windows Task Scheduler or cron) to run `php artisan schedule:run` once per minute. Set `APP_TIMEZONE=Asia/Manila`. Never commit real `.env` credentials or real people's photos.
