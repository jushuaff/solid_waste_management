## Shared data / workflow rules
- Inspections represent **observed pickups**; missed-pickup case reports are a separate dataset.
- Household data is minimal and linked to a zone. No real citizen data should be seeded for demonstrations.
- Compliance rate = compliant inspections / all inspections × 100 (avoid divide-by-zero; explain sample size).
- Diversion rate = diverted MRF weight / total recorded MRF weight × 100. Use only comparable logged weight categories and label this as a **record-based illustrative metric**; reconcile with the adopting LGU's officially required denominator before regulatory use.
- Dashboard thresholds for the academic prototype: green >=80%, yellow 60–79.99%, red <60%.
- Alerts need an automated cron/scheduler; an implemented command alone does not mean background scheduling is running.
- Report urgency threshold: over 48 h unresolved; escalation recipient is the designated active barangay admin/coordinator.
- Sample records and example collection arrangements do **not** establish an official barangay schedule or compliance claim.
- These data are isolated per barangay installation; shared multi-barangay hosting is out of scope.

## Local setup and acceptance commands
```powershell
php -v
where.exe php
php --ini
php -m | findstr /I "mongodb openssl mbstring fileinfo"
composer install
Copy-Item .env.example .env  # only if .env does not exist
php artisan key:generate
php artisan migrate
php artisan db:seed
php artisan route:list
php artisan test
php artisan serve
```

For periodic online alerts configure Laravel's scheduler (Windows Task Scheduler or cron) to run `php artisan schedule:run` once per minute. Set `APP_TIMEZONE=Asia/Manila`. Never commit real `.env` credentials or real people's photos.
